# Requirement 蜂群探索与拷问机制讨论稿

状态：设计已用于技能修改，Astra/medium 实施及首轮输入隔离定向复审均通过；已同步 Codex，尚未 Git 提交。

## 目的与边界

改善需求讨论在第三轮过早收敛、缺少边界挑战的问题。保留主 Agent 和恰好两个探索者，不新增角色或控制器门禁。轮次增加到至少 3、至多 12；更长讨论不等于更可靠，也不保证消除共同盲区。

本次只设计 Requirement 内的自主讨论。面向人类的 brainstorming 及最终需求授权保持原有边界；借用 grilling 的问题树、依赖前沿和反向追问，不复制其全部人类访谈流程，不替人类创造偏好。

## 分工

- 主 Agent：主持人、问题提出者、遗漏发现者和结论核对者。掌握全部相关人类上下文，维护问题地图；代理已表达的意图，不替人类作未授权取舍。
- 价值与边界探索者：探索用户目的、场景、替代方向和最小交付；挑战过度风险控制及偏离目的的方案。
- 风险与反例探索者：探索假设失效、遗漏场景、约束组合后果；保留 blackbee 职责，同时提出最小可行替代或控制，不只否定。
- 双方都建设、都质疑；不强制制造反对意见。

按问题指定主答方和交叉挑战方；视角分责，关键证据共同核对，不要求双方各做一次完整需求分析。

## 继承此前的人类讨论

从全部可访问的相关历史提取讨论基线，不只读取调用技能时的一段文本。区分人类明确目标/约束/偏好、已确认选择、拒绝方向、临时候选、未决问题及 Agent 建议/推断；重要结论保留原话或来源定位、时间顺序和成立条件。

已有脑暴讨论足够时只补缺口，不重新访谈；已有同一基线的明确记录确认时不再索取同样确认。无可用确认时展示简短基线，校正歧义后取得记录确认。缺失完整历史或可选时间戳不自动阻断，但不得虚构来源或确认。“听起来不错”“我再想想”不自动成为产品选择或最终范围授权。

第一轮独立意味着不看同伴输出、未被主持人推荐锚定，不意味着丢弃人类上下文。后续明确的人类修正以 amendment 覆盖相关旧结论，同时保留原始来源；蜂群共识不能覆盖人类约束。

新探索首轮用隔离上下文创建两个线程，提供同一来源绑定的无排名基线视图。保留人类明确选择及标为建议的历史 Agent 方向，不附主持人当前推荐/排名、同伴结论或未过滤会话。冻结原记录不改写，来源可供核对事实与人类承诺。已有探索恢复复用原线程与轮次，不重新开启首轮。

## 轮次与问题组织

1. 第一轮：同一冻结上下文下盲独立探索，主持人不先给推荐。
2. 第二轮：共享实质发现，交叉补漏，整理问题地图和待核对假设；仍以发现和探索为主。
3. 第三至十二轮：主持人提出主题问题 → 双方探索回答 → 交叉挑战 → 主持人整理、核对冲突、更新边界 → 下一轮。

常规每轮 2–3 个主题组，总计 3–6 个紧密相关的问题；这是容量建议，不是配额或代码门禁。主题按影响和依赖组织，只问当前能够回答的问题；依赖未知答案的分支留待后轮。明确标记的条件分析可以讨论“若选择导出，会影响哪些边界”，但不能据此确定导出需求。仅剩一两个有效问题时允许例外，不凑数。问题组不必强迫双方对无关事项重复答复。

一轮包含主持人派发当前前沿问题、双方独立作答、必要的对照挑战和主持人整理。轮内允许澄清原问题或纠正证据，新解锁的实质问题进入下一编号轮，不能把无限讨论藏在同一轮内。第一至二轮暂缓推荐与排序，但有证据证明不可行的方向可以排除。

共享双方原始的结构化实质输出：观点、来源定位、适用条件、事实或假设标记、反例和未知项，而不只是主持人的推荐摘要。主持人的遗漏发现也用相同格式；摘要只作导航，双方可以核对原条目并指出压缩失真。必要时提供授权范围内的原始证据引用；不共享私有思维链、密钥或越权材料。

双方每轮必须回答本轮指定问题并报告结论变化；no_material_delta 只表示结论未变，不能替代回答、依据或覆盖说明。风险探索者可以提出同一问题框架下更小的建设性方案，不限于完全不同的候选方向。

## 交叉挑战与纠偏

每轮检查对方最薄弱的结论、遗漏场景、共同接受的无据假设，以及会让自己改变判断的事实。主持人另外从用户目的、受损对象、失败后果和约束组合检查共同盲区。

轻量记录重要问题和结论的稳定引用、来源及适用条件。新回答与旧结论核对后区分：

- 真正矛盾：相同条件下结论不兼容，优先核对双方依据和影响。
- 条件细化：明确一般情形与新增例外，不能含糊合并。
- 有据修正：保留旧结论及撤回理由，不默认最新回答正确。
- 人类意图变化：模型不能自行决定，呈现真实取舍给人类。

低影响措辞差异不自动升级为新讨论。重要质疑只能以证据反驳、方案调整、明确残余风险或待人类取舍处置；“已考虑”“后续注意”不算解决。纠正事实、撤回尚未授权的过度建设不需要每次请人类决策。无法裁定的冲突保留互斥假设及影响，不冻结无依赖的其他主题。

## 范围防膨胀

新风险不自动变成新需求。说明触发条件、证据或假设、与当前用户目的的关系、影响和最小控制代价。优先评估操作、验证、配置、缩小边界或直接实现，不默认新增平台能力。

新增范围仍需当前 NEED 和明确收益；平台化仍需既有 PLATFORM_RECEIPT。小概率、无依据的可能性明确为假设，不以穷举风险和实现细节耗尽轮次。

## 收敛与人工取舍

第三轮后可结束自主探索，但不能仅凭 no_material_delta 或双方一致。应能说明主要场景和高影响边界已被挑战、关键假设已溯源或明确未决、重要矛盾已处置、候选差异及非目标清楚，且没有剩余 Agent 能安全推进的高价值问题。

结束探索不等于获得产品授权。尚有关键人类取舍时，在简短 Decision Brief 中列候选答案和影响；不得将未决方案写成 READY_FOR_INTENT 或获批。事实由 Agent 在授权范围内调查，偏好由人类决定，不每轮索取确认。

达到第十二轮时停止自主扩展，保留未决项和证据，不强制共识。人类补充答案后只检查受影响边界，不默认重跑所有讨论；若覆盖原脑暴中的选择，保留原记录并明确新的替代关系，不把旧记录继续当当前意图。未耗尽轮次时，在剩余轮次内定向挑战；耗尽后可以合并人类明确选择，但若仍需新的实质探索，应保持未决、说明所需后续并请人类决定是否另开探索。说明原因本身不授权超过十二轮，也不能静默清零绕过上限。

每轮只播报讨论主题、实质变化和下一步；记录可检查结论，不输出私有推理。详细记录服务于讨论，不要求为低价值问题维护大量表格。

## Astra 讨论要点与处置

本次审查仅针对设计；未检验实际讨论效果或实现。Astra 读取现有 Requirement、两角色定义及 grilling 后提出五项设计歧义和一项非阻塞成本提醒：

- DESIGN-01：区分自主探索结束与产品授权；人类偏好不可由 Agent 穷举得出。已纳入收敛规则。
- DESIGN-02：依赖前沿优先于题数，明确一轮边界和条件分析。已纳入问题组织。
- DESIGN-03：双方都可建设；后续必须回答问题，不能以“无增量”代替。已纳入分工和共享规则。
- DESIGN-04：主持人摘要不是唯一证据通道，共享原始结构化实质输出。已纳入证据共享。
- DESIGN-05：事实纠正不等于范围授权，未能裁定的冲突不冻结独立主题。已纳入纠偏规则。
- DESIGN-06：小需求不凑题数、候选数或反例数；三轮有效挑战后结束仍然正常。作为成本限制保留。

仍有的限制：双方和主持人可能共享同一盲区，来源也可能不完备。该机制增加发现机会，不证明需求绝对完整。实施后应观察质疑是否真正改变结论、是否发现跨轮冲突、是否减少无据扩张，而不以轮数作为质量指标。

修订后的 Astra 定向核对认为 DESIGN-01–05 已实质处置，可以作为技能优化的设计基线；另要求明确“说明原因”不能自动授权超过十二轮，已纳入。未新增 Agent 或控制器要求。

## 待讨论的检验样例

- 同一“禁止存储”约束，后轮却建议保存失败请求：识别例外还是实质矛盾，不能直接采用最新答案。
- 发现罕见故障后提出通用重试平台：核对当前收益，优先最小控制，不自动新增 NEED。
- 双方同时假设用户接受降级：共识没有人类依据，必须保留为取舍。
- 最后仅剩一个关键权限边界：允许专门讨论，不人为制造第二个问题。
- 第十二轮仍无法知道用户偏好：终止 Agent 空转，呈现选择；不能伪装为已收敛。
