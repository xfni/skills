# Flowctl Deterministic Orchestration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement a deterministic Flow v2 controller for mechanical artifact, checkpoint, review, and transition state.

**Architecture:** A thin `workflow-v2/flowctl.py` entrypoint calls focused stdlib-only modules in `workflow-v2/flowctl_lib/`. Mutations pass through one locked state store; artifacts, reviews, resume discovery, and handoffs derive facts instead of trusting Agent claims.

**Tech Stack:** Python 3.10+ standard library, unittest, JSON/JSONL, SHA-256, POSIX file locking.

**Spec:** `docs/superpowers/specs/2026-09-14-flowctl-design.md`

## Global Constraints

- Preserve Flow v2 artifact byte and path contracts.
- Support default discovery and explicit arbitrary-node inputs.
- Never trust caller-supplied digests, retry counts, success flags, or failure classes.
- Keep the implementation stdlib-only.
- Emit machine-readable JSON for every normal command result.
