# Flow v2：Agent 主导、控制器最小核对设计

版本：设计 r2，2026-09-17。状态：已按人类授权实施，Astra/medium 实现限定复审通过；未部署、未 Git 提交。原设计复审与本轮实现审阅分别记录，不互相替代。

## 1. 目标与授权范围

控制器为流程服务。Agent 决定下一步、判断业务含义并处理未知情况；控制器核对当前动作中可确定的事实，并可靠记录接受结果。控制器不能枚举所有异常，也不证明所有模型输出正确。

本设计针对现有 Flow v2 控制器的精简，不改变 requirement → intent → roadmap → spec → plan → code → integration 的职责、现有强制审阅路线、人工需求确认或宿主权限。用户已同意此方向，并在设计讨论后明确授权更新工作流与控制器及提交 Astra 实现审阅。

REQ-1：信息不完美不能自动成为全流程阻塞。
REQ-2：未执行、未知、失败、明确撤销的结果不得声明为通过。
REQ-3：恢复不重新规划，不删除历史，不强迫补做无关前序手续。
REQ-4：无法机械判断的适用性、业务范围、覆盖充分性由 Agent 决定并注明来源。
REQ-5：接口和部署尽量保持兼容，不增加正常路径审批轮次。

## 2. 已观察问题及其含义

| 现象 | 设计原因 | 本设计响应 |
|---|---|---|
| 已批准替换 Requirement，但旧 route-back 把流程拉回 | 历史待办与当前执行位置被混为一体 | 由 Agent 处置旧待办，保持当前位置 |
| 新 Code 被三个失效旧评审占满预算 | 当前对象预算与历史讨论次数混用 | 只限制当前对象的运行／补充评审次数 |
| resume 丢失 GPT lane、回退阶段 | 恢复重新推断整条工作流 | 注册记录和实际交接优先，缓存可重建 |
| Integration 辅助探针使整个快照变化 | 字节差异被当成业务实现失效 | 返回变化事实，由阶段 Agent 判断影响 |
| 缺少旧 Plan 场景表，连环境失败都不能登记 | 完成要求被套用到失败记录 | 失败事实可先记录，覆盖交给 Agent |
| 终审误登记为 GPT，触发主审上限 | model 与 review role 容易混淆 | 返回真实 lane 及操作提示，不替 Agent 改写审阅身份 |

当前工作区已有部分故障修复，不等于本设计已落地。代码导航：state.py 的 register_artifact/validate_upstream；resume.py 的 reconcile_resume；reviews.py 的 begin_review/has_passed_review/next_review_action；handoff.py 的 accept_handoff；integration_results.py 的场景匹配。

## 3. 选型与非目标

采用：在现有模块、CLI、状态文件和事件中收敛核对规则。保留实际收据与原子记账，移除全局完备性要求和自动业务推断。

不采用完全提示词控制：会重新允许无收据声明评审完成。不采用新事件平台／工作流引擎：增加迁移成本，不能解决语义判断不可机械证明的问题。

非目标：新异常分类全集、万能 override、新 AgentDecision 服务、多套快照框架、业务数据库适配器、新强制审阅环节、改写业务控制器文件、绕过宿主安全边界。

## 4. 分工与事实保证

| Agent 负责 | 控制器负责 |
|---|---|
| 选择授权范围内下一步 | 核对并记录本次接受的动作 |
| 业务范围、改动影响、证据充分性、测试覆盖 | 身份、文件读取、实际摘要、收据绑定和记录来源 |
| 未知问题调查、修复位置、是否需重审 | 返回当前必要事实缺口及局部修复提示 |
| 跨修订问题收敛、必要时问人类 | 当前对象有限重试、重复执行保护 |
| 解释历史保证适用性并承担判断 | 保留原保证对象，不创造新审阅 PASS |

三个不同问题不能压缩成一个全局 valid 布尔值：

1. 原收据是否真实可读、未篡改、未明确撤销？
2. 它原来证明的对象是否与本次动作对象相同？
3. 对象不同时，Agent 是否判断某项历史保证仍适用于本次变化？

控制器核对前两项；第三项是 CALLER_ATTESTED 的处置，不是 CONTROLLER_EXECUTED 的新收据。现有 GPT 调用者提交报告不能被描述为控制器独立证明模型执行过。

明确撤销的保证不能凭“仍适用”复活；必须重新完成其必要流程。已知 FAILED/BLOCKED/未知不能用适用性处置改成 PASS。历史确曾完成的交接保留为历史事实，不等于当前交付仍可声明通过。

## 5. 动作级最小检查

所有受控状态变更保留 issue/worktree/操作对象绑定、expected-revision、文件锁、崩溃恢复和原子记账。只读取本次必要工件或收据，不在日常命令中全量 audit。

| 动作 | 必要检查 | 不再作为门禁 |
|---|---|---|
| status | 控制器可读取，身份可解释 | 所有历史字段、文件、审批 tuple 完美 |
| artifact register | 目标类型/issue/milestone 清楚；文件可读；计算实际摘要 | 完整前序链、辅助元数据、文档模板细节 |
| review begin / run | 对象可定位；本次 review role 明确；必要前置收据和运行预算；外发视图及实际宿主权限 | 无关历史评审、业务 finding 细节、未知异常必须先归类 |
| review submit | 原 attempt 可确定；终态可读取；报告绑定及实际来源；执行期间变化被记录 | finding 的完整辅助字段或措辞符合模板 |
| handoff accept | 当前阶段/对象正确；本次政策要求的终态收据或既有允许的 gap 条件；无未处置的直接矛盾；必要批准未被撤销 | 全历史 dependency tuple、精确场景全集、旧解释性字段 |
| signal record | 当前 issue/run/stage；信号动作清楚 | FAILED/BLOCKED 需完整成功测试记录或 Plan 场景表 |
| resume | 恢复当前登记位置和实际待办；核对本次使用的对象 | 目录扫描重新选择阶段；补做无关历史手续 |

字段不足但对象与结论可确定时，由代码补计算值或给警告。身份歧义、不可读取的必要证据、不可解释的终态不能由默认值补成成功。

没有必要 review 不是“没有矛盾”：仍不能接受依赖它的通过声明。review role、审阅顺序、外部 retry/fallback、实质修复后的 fresh Astra consistency 和有条件完成政策保留。字节变化本身不再自动等同于必须新跑所有角色。

交接使用历史保证的规则明确如下：Agent 有依据判断批准范围及获审实现未变时，原真实 PASS + 单独的适用性处置可以满足该角色的保证要求，包括未被实质变化取代的原一致性收据；最终结果必须披露两个来源和原证明边界，不能标为当前新对象 CONTROLLER_EXECUTED PASS。若范围或获审实现变化、存在已知未解决 blocker、保证已明确撤销，则处置不能替代该角色的重新审阅／必要人类确认。缺少原真实收据也不能通过处置补出一个角色的 PASS。

## 6. 控制器与 Agent 的最小往返

Agent 提出动作 → 控制器返回确定事实/缺口 → Agent 调查和选择处置 → 控制器核对客观前提并记账。

反馈仍是命令结果，不新增阶段状态或业务结果枚举。继续使用四种状态和三种结果（可为空）。continue/warn/repair/refuse 只是本次动作反馈，不是持久化生命周期。

保留现有 JSON 返回的 ok/code/details。details 可补 action、facts、warnings、missing、suggested_actions、state_revision；它们帮助 Agent，不要求 Agent 凑齐这些字段才能继续。语义不确定的文字不由代码审判。

需要保存“为什么继续”的时候，复用现有阶段报告／证据引用。只新增一个共用可选参数 --disposition <path>，供 register/resume/handoff/snapshot 等已存在命令引用处置材料，不增加 decision/override 命令。该参数唯一表达 Agent 判断原批准范围与获审实现未变、继续使用列出的历史保证／关闭已解决旧待办，不用于泛化的异常豁免。需要修改范围或实现时用既有 route-back/review，而不是处置参数。没有变化的正常路径不需要它。

材料使用小 JSON：非空 reason、依据文件引用 evidence；使用历史审阅保证时提供 source_attempts，处理旧路由时引用其原事件。当前对象从命令参数推导，旧摘要从原保证读取，新摘要由控制器计算，禁止要求 Agent 手算或重复提交 tuple。说明内容可以自然语言；代码检查引用可读取、原收据终态及来源、无明确撤销或已知矛盾，记录材料实际摘要和 CALLER_ATTESTED 来源。不要求分类所有异常或填写扩展字段全集。

处置绑定的是一项变化及其旧/新对象和原保证，而不是单个 CLI 动作名。控制器在首次引用时计算并保存这些绑定；后续同对象动作从事件／当前记录复用该处置，不要求每次重交。对象再次变化、相关保证撤销或出现新 blocker 时，原处置不能自动扩大范围。涉及 Code 时绑定新实际 snapshot；涉及旧待办时绑定对应事件。缓存可派生，历史材料和来源不得改写。

该参数只能记录语义处置，不能修改原审阅结论、执行来源、重试次数或人工／宿主授权。处置失配时只返回本次关联缺口，不把 issue 拉回 Requirement。

## 7. 工件变化与阶段位置

登记是更新对象事实，不是改变当前执行位置。首次从任意阶段接入时，在现有 init 上增加可选 --stage（默认 flow-requirement）与 --milestone（局部阶段使用），以 Agent 明确选择的入口建立位置，再 register 对应工件。建立 Code 入口不伪造 Spec/Plan 已批准或已审；直接节点使用由其 Agent 按既有职责确定必要当前范围。缺少历史文档仅告警，不补前序流程。

这两个参数仅对新 controller 生效；已有 controller 的 init 保持原位置和 gate，不能用入口参数覆盖或重定位。不扩展 resume 输入图为新入口协议，不新增 start/advance 命令。已有 CLI 命令及必需参数保持兼容，允许上述少量可选扩展。

对已有运行，登记旧阶段或新内容不自动删除下游工件、快照、coder 状态、gap、handoff 或 completion。记录旧/新摘要及当前绑定差异；不依据阶段顺序推断业务依赖失效。

Agent 判断补解释、元数据维护：记录处置后继续当前位置。Agent 判断范围或获审实现改变：通过既有 route-back、必要人类确认、重新评审等动作明确撤销受影响的当前保证。撤销可以覆盖相关下游，但不是摘要变化自动触发。

下游要引用已变化的保证时，控制器不得静默重写 upstream tuple 成新值。记录原绑定；确定绑定不匹配时返回 Agent 处置，不能把重新登记当成重新评审或需求适配。未绑定的缺失历史不创造门禁。

已完成运行中 register 补材料保留 complete，不删除旧保证或触发新开发；该登记不构成新内容获审的声明。实质新增工作通过现有 FLOW_RUN_ROUTE_BACK 明确 owner 重新进入对应工作，不自动在登记时重开，也不在本次设计增加 run 管理。旧完成声明仍保留其原对象范围。

## 8. 快照和评审

第一版继续使用现有 whole-worktree freeze、外发排除和 stdout/API-only reviewer，不增加业务/测试/报告三套快照身份。

开始外部 review 时当前视图必须正确过滤和冻结。review 期间发生变化，原报告仍绑定原视图；记录差异并返回 Agent 处置，不把报告自动升格为当前对象通过。

Integration 辅助测试改变快照时，不回退当前阶段、不重置 coder、不删除 Code 原交接。Agent 检查变化：辅助变化可记录当前处置并继续；影响获审实现则 route back。控制器不能机械证明“非关键”。

最终报告列出原外审快照/收据、之后的变化和 Agent 处置。当前阶段完成是 Agent 对交付负责的声明，不等于最后整个 worktree 都经过外审。历史 review PASS 不改绑；已知 blocker、明确撤销或真正必需的未完成 review 不可用辅助变化处置绕过。

评审有效性查询统一用于 begin/submit/handoff/status/resume，返回事实而非各模块重算全局 eligibility。lanes 是可重建索引；历史 consistency_attempts/eligible 注释不独立决定推进。

明确撤销的来源保留；单纯绑定不匹配与明确撤销分开。resume 不因摘要回到旧值而自动复活撤销收据。临时差异消失可恢复对象匹配事实，但不得擦掉实际撤销来源。显式 route-back 可以撤下当前索引，但被历史收据／交接引用的 snapshot、报告、gap 和批准记录应留在事件／证据中，不能只有“不删 events”却删除事件外原保证材料。

当前对象/role 的终态评审次数、运行失败和协议重试由确定记录计算，不计已失效旧对象。现有限次策略保留，只限制本次受约束的调用；到上限返回修复/备选动作，不自动制造全局业务 BLOCKED。跨修订重复无实质变化由 Agent 按原技能收敛，不借无限新摘要伪装收敛。

## 9. 恢复、旧路由和暂停

已有 controller 时以登记位置和已接受 handoff 为准；pending_action 重新派生为建议，不是授权范围内唯一合法操作。仅核对被请求的本次动作，不用目录扫描寻找“更深/更合适”阶段。

扫描仅用于首次接入或 Agent 明确修复缺失路径。多候选时返回候选，Agent 选择已知当前路径；不能要求人类先处理所有旧工件歧义。已登记路径存在时，不受无关同 revision 历史文件阻塞。

旧 route-back 的相关替换对象已登记且有必要批准时，Agent 可提交处置引用，关闭对应旧待办；控制器核对目标并保留历史。不会要求改 Requirement 制造新 revision，也不重复已有前序 handoff。

明确人工/宿主 gate 的实际约束范围保持不变。解除必须显式 RESUMED，引用当前 pause 的原 signal revision，并记录 Agent 得到的解除事实；新增引用是现有 signal 的兼容扩展，不要求旧历史预先拥有此字段。控制器从事件定位当前 pause，能确定时自动补引用；存在歧义交 Agent，不清除暂停。

控制器不验证自然语言条件是否真的满足；宿主授权以实际宿主权限执行。旧已结束 pause 字段缺失只警告；明确未结束 gate 不能因历史不完整推定已解除。需求未批准可能限制所有实现，Agent 不得自行缩小它的范围；外发被拒绝不能换工具实施同一次被拒绝外发。

## 10. 测试结果和未知故障

Plan 场景全集匹配、精确说明字段、gap 文本和覆盖充分性不再作为日常 register/handoff/resume 门禁，保留可选 audit。已知结果对账可以由代码计算，缺失覆盖由阶段 Agent 判断并记录。

完成的最小证据是：清楚的当前测试对象、可读取的证据引用、明确终态和阶段 Agent 的执行/覆盖判断。不要求控制器重演所有测试。CALLER_ATTESTED 不等于控制器证明真实执行。

FAILED/BLOCKED 可使用启动失败、权限拒绝、探测错误或未执行事实证据，不要求成功请求、完整场景表或结束清理证明才能登记障碍。Agent 可继续获准且不依赖该障碍的检查。

当前测试范围内已登记 FAILED/BLOCKED/未知不能静默汇总 PASS；只有新的实际结果或既有允许的有条件完成政策能替代，且要能定位相同测试对象及被替代的原结果，历史结果不删。替代关联使用原记录引用，不要求把所有测试 case 对齐成严格全集。跳过生产回放仍受现有决定和 gap 政策约束，不因删场景 matching 自动获得跳过许可。

未知 vendor 文案由 Agent 调查，不要求先枚举成错误类型才允许诊断。Agent 判断单独注明来源；不能据一句“额度不足”提升 raw unknown/FAILED 为可信运行错误或 PASS。可靠退出码、runner 结构信号和真实执行记录支持现有有限 retry/fallback。桥接协议修复不能篡改原结果，只可重建可证明的原信号或重试。

控制器错误返回当前动作未被接受及具体修复提示，不自动 FLOW_RUN_BLOCKED/HUMAN_GATE、不回退需求。Agent 可继续只读诊断和材料准备；要求可靠审计的外部操作在无法记账时暂缓，避免重复执行。

## 11. 兼容、落地范围与回退

不要求重建旧状态、清空预算或删除旧 events。保留 schema_version、current_stage、pending_action、lanes、eligible 等旧字段；派生缓存缺失可从确定事实补齐，不能回补不存在的 PASS。旧客户端继续收到原字段，更新技能不再将它们视为全部合法行动的枚举。

实现范围限定为现有 state/resume/reviews/handoff/signals/integration_results/cli/errors 及配套 contracts、Flow skills、行为测试。保持 authorizations、审阅 runner、外发过滤、文件锁/事务核心边界，不另建工作流层。少量纯函数统一对象关联、收据事实及动作反馈，不搞通用 gate registry。

严格 artifact verify/audit 保留显式诊断用途，但不能成为常规恢复的前置手续。模块内部采用宽容读取，不把结构诊断误当业务失败。

部署时整体同步 flowctl.py、依赖库、契约及所有技能，逐文件核对。旧会话需重读技能；不直接改业务 state/events。实施前保存包版本与状态备份。回退只替换可执行包、不覆盖已追加事件，但不承诺旧包理解所有新处置：先只读检查实际兼容性；不兼容时保持状态、停用旧包写入并修复／恢复兼容新包，可继续安全诊断。不得恢复旧 state 来抹掉新事件或用旧严格规则重新推断阶段。部署失败不退回 Requirement。

AC-2：登记 Requirement 补解释保留 Plan/Code/历史交接和当前阶段；Agent 处置可继续，旧 PASS 仍绑定原对象。
AC-3：范围真正变化经明确 route-back 撤销相关保证；适用性说明不能复活它们。
AC-4：旧 lane 丢失、有原收据时可重建；缺失必要终态时拒绝该交接，不拉回前序。
AC-5：三次旧 Code 评审不阻止新对象；同一当前对象限次仍生效，角色计数分开。
AC-6：Integration 新增探针保留当前位置与原审阅范围；生产实现变化经 Agent 判断返回修复，不宣称新快照外审通过。
AC-7：legacy Plan 缺场景表时可记录启动 BLOCKED；已知失败和未执行不得完成为 PASS。
AC-8：前序文档缺失允许任意节点接入；已有登记路径不受无关历史候选冲突阻塞。
AC-9：协议错误保留原始事实，有限恢复或返回 Agent；不自动业务拒绝、不生成 PASS。
AC-10：RESUMED 只解除关联 pause；真实宿主拒绝和人工 gate 不能由 disposition 绕过。
AC-11：STATE_CONFLICT 重新读取后不重复外部执行；记账故障暂停需审计操作而保留位置。
AC-12：旧 CLI/state 可用；普通无变化流程不需要新增处置材料、审批轮次或人类菜单。

风险权重优先覆盖撤销复活、对象错绑、虚假完成、权限绕过和崩溃重复执行；其次验证恢复幂等与前进优先。用命令序列和临时业务状态副本验证，不只断言提示词字符串。

## 13. 待设计审阅与保证边界

Astra 审阅范围：本设计的可实施性、动作必要条件、Agent 处置接口、旧字段兼容、是否误增门禁，以及 AC 是否覆盖最近故障。讨论可修订设计，不隐含实施授权。

本设计不保证 Agent 语义判断永不出错，不证明 CALLER_ATTESTED 的实际执行，不保证全部未知错误自动恢复，也不承诺最终整个 worktree 经过外审。承诺的是不改写原保证、不制造成功、不越过真实权限，并将不确定性限制在确实依赖它的动作上。
