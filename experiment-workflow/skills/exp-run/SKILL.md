# 数据实验工作流

以可信证据回答问题，不以正向结果或实验次数作为成功标准。独立于开发 Flow；两个技能、四个角色、少量记录，无控制器、详细 Spec 或审批收据门禁。

首次运行完整阅读 [实验约定与证据](references/experiment.md) 和 [角色与线程](references/agents.md)。两份参考随本技能安装。数据采集需 `$exp-data`；未安装时说明缺失能力，不假装已经执行。

## 讨论与执行确认

讨论不属于实验 Goal，也不采集生产数据或运行实验代码。它只产出当前 `EXP-*` 的可确认方案；每次实验用 `EXP-*` 代号，默认可按已有记录顺序分配，避免覆盖。

1. 从相关人类历史提取目标、假设、拒绝方向、所需结论及未决项；区分人类选择与模型推断。必须有一个人类提供的需求 issue；缺失只索取，不发明。
2. 按下方「结合项目逐项收敛」与人类讨论，先确定实验要帮助做什么决定，再从项目现有能力推荐最小可行方法。说明数据来源、生产只读范围、比较对象、主要指标与判定依据、脱敏、实际接收者和结论级别；不要假定之前聊天已授权采集。
3. 人类目标与初步方案具备后，与 `exp_reviewer` 进行轻量收敛：默认 2 轮、最多 4 轮，每轮处理少量相关主题。分享方案与可核对的来源，审阅者挑战样本可比性、信号损失、可归因性及成本；主持者核对矛盾后修订，仅将影响目标、结论、成本或执行边界的真实取舍返回人类，不逐条转发审阅意见。必要时咨询数据/实验角色；内部讨论轮数不作为人类问答轮数，共识不替代实验证据，风险不自动扩展目标。
4. 先有方案，再估算并协商配额及停止条件。不足以支持所需结论时返回方案讨论；实质变化做定向核查，不暗中清零讨论轮数。把当前方案、修订标识、一次性执行范围、推荐/备选、取舍、成本、残余限制和预计结论压缩成可读摘要，然后明确询问：`是否按 EXP-xxx 的当前方案展开实验？`。确认前不采集生产、不运行实验代码，也不创建或替换 Goal。
5. 只有明确指向当前 `EXP-*` 及刚呈现方案/范围的肯定答复才启动。带有未解决条件、实质修改或语义不明的回复先修订/澄清，不把它当确认；确认后的范围变更只重问受影响部分。一次确认的具体内容见 [实验约定与证据](references/experiment.md#执行范围)。
6. 确认后先核对 worktree。开发后的验证优先复用当前已关联的 feature worktree；只有当前在 `master`、worktree 与 issue 不匹配，或候选实验确有文件/依赖冲突时才创建独立实验 worktree。不同实验可共用同一正确 worktree，不造嵌套 worktree。按项目要求选择命名/来源，否则从本地 master 创建同级 `feature-<issue>-exp`。issue 含路径字符时保留原标识并说明安全目录映射，不能直接拼入路径。不是 master 上做实验，也不忽略已有脏改动。没有 master 时说明并确认实际基线，不自行拉取/改主分支。宿主/项目要求恢复会话时给出真实会话命令并等待；权限失败不退回主分支。

## 结合项目逐项收敛

每次只问一个会影响实验的决定。提问前定向检查当前项目的相关代码、配置、运行文档或已有实验记录；先简短解释「在哪里看到什么 → 能证明什么/尚未验证什么 → 为什么影响本实验 → 可选方式与推荐理由」，再提问。缺 issue、项目位置等定位信息时可以直接索取，不假装已查项目。具体示例与执行方式见 [实验约定与证据](references/experiment.md#逐项讨论)。

继承已经明确的人类选择；代码能回答的事实由 Agent 查证，普通实现细节由 Agent 决定。只问影响目标、解释能力、数据处理/去向或成本的未决项；没有实质未决项就进入确认摘要。查过且仍适用的证据可复用，不为每次提问重新扫描全仓。新证据推翻前提时指出具体冲突并定向重开该项。

先确定所需结论，再推荐已有回放、小型分析脚本、隔离候选实现或必要组合。方法会改变所需结论、成本或边界时才让人取舍。文件内容只能证明代码/配置声明，不能证明线上生效、连通性、权限或数据质量；未查到只能说本次检查未发现。人类不知道答案时，说明还能查什么或保留有停止规则的待验证项。

涉及数据去向，直接说明哪些内容会离开本地、交给哪个接收者/端点/模型、用于什么、上限多少。逐项选择只是方案偏好，最终确认才授权按完整执行范围开展实验。

## 实验 Goal

worktree 核对完成后、首次数据动作之前，建立独立且由当前 `EXP-*` 拥有的宿主 Goal。目标只包括：数据摘取、多轮试验、数据评测/独立审阅、报告及必要清理；讨论、开发实现和其他实验不属于它。

- 先查询当前 Goal。没有未完成 Goal 时创建实验 Goal；已有未完成 Goal 时，只有宿主明确提供原子替换（失败时旧 Goal 完整保留）的能力，才以当前实验 Goal 替换并核实成功。替换是人类刚才肯定答复授权的一部分，不把旧 Goal 误标为完成或阻塞。
- 不能把分步 `clear + set/create` 当作原子替换：即使人类已确认实验，也不先清除旧 Goal 再赌新 Goal 会建立成功。若宿主不支持原子替换，或替换调用失败，保留旧 Goal 原状态，解释“已确认实验方案，但宿主未能安全建立独立实验 Goal”，给出宿主实际可用的恢复动作；**不开始**数据摘取、回放或评测，也不编造后台持续执行。不得发明 `/goal`、`thread/goal/*` 或其他宿主命令。
- 在实验记录中保留 Goal 标识、当前方案修订/摘要和执行范围，供恢复核对；这只是关联记录，不是控制器或审批收据。
- 数据交付、单轮试验和审阅返回均自动续接下一项已确认动作，不能完成、清除或替换实验 Goal。Goal 也不授予生产、数据目的地、网络、预算或写入权限。

## 自主执行

确认后持续推进，不在摘取完成或每轮结束时要求人类另发下一技能命令。

- 给 `exp_data` 数据任务，在 `$exp-data` 约定下只读采样、核验质量、脱敏并交付可用性说明。先查代码/config/现有运行文档，再问缺失来源；用现有数据库/服务客户端，不强制本地 Docker 或标准采集适配器。脱敏数据和允许的证据可给 reviewer，原始数据/映射表/密钥不可。
- 给 `exp_worker` 顺序任务，持久复用线程，明确本轮方法与所需结论。已有入口够用时直接回放；缺少匹配/统计能力才写最小分析脚本；假设确需新逻辑才在指定实验路径实现隔离候选。允许必要组合，不默认创建新框架、配置开关或服务。保持生产业务实现/默认配置不变；通过实验模块或副本验证候选，不部署、不写生产。新增驱动/指标/候选代码做与风险相称的验证；复用回放不为形式额外造代码。保存可重建基线、样本版本和运行条件，记录每次尝试与真实输出，不能只发摘要或最佳轮次。
- 根据结果在已确认策略、执行范围与剩余配额内安排下一试验；预先约定的停止/降级条件成立即可自主结束，不再问是否接受证据不足。范围内的采样、回放、评测、允许的 iBrain 调用与重试不重复索取授权；需要超配额、改目标，或实际超出已确认数据源、接收者/数据类别、端点/模型、样本上限或本地依赖范围时才请求取舍，不换实验代号绕过上限。
- 主 Agent 持续播报“正在做什么、发现什么、下一步是什么”。审阅结果只返回主 Agent，不直接写 worktree；主 Agent 与其他写角色分清文件所有权。

## 核验、恢复与结束

结果审阅与方案讨论分开：让 `exp_reviewer` 根据明确允许的实际代码、脱敏数据、完整轮次记录和原始执行证据核验关键结论，而不是只看主持者摘要。能安全复算的指标做风险加权抽查；无法重现的结果说明证据限制。对影响结论的重要发现修正并定向复验，纳入剩余配额；非阻塞建议不引发无限循环。

负面或证据不足也是有效结论；不创造未约定的 no-go/上线标准。前后匹配观察不能自动证明上线因果，复验集用于调参后不再算独立证据。已知失败、未完成、排除项和退化必须披露。

中断恢复先读实验记录，核对 Goal 标识是否仍是当前 `EXP-*` 的活动 Goal，再核对 worktree、代码/数据、已有线程或进程、真实完成状态、执行范围和剩余额度。Goal 匹配且仍活动时才自动续跑；缺失、已结束或属于另一实验时不自动替换、不重采，先解释差异并等待真实恢复动作/人类意图。未知完成的半成品不算有效结果；模型升级不意味着实验可以重跑或预算清零。

输出遵循当次目录 → 项目 AGENTS.md → 全局 AGENTS.md → 默认 `.ai/issue/<safe-issue>/experiments/<EXP-id>/`，注明原 issue 与目录映射。保留实验约定、逐轮记录、最终报告/证据索引；可合并文档，不因非关键字段或格式不齐阻挡。所有实验更新在已核对 worktree 内，原始数据按受限路径与 Git 排除规则单独管理。

最终先给人类简短结论：改了什么、有什么效果、代价/退化、可信度、不能证明什么、建议与报告位置。可在检查暂存范围后本地提交代码、报告和安全证据；不提交原始数据/映射表/凭证，不自动合并或推送。停止自建临时服务、处理自建副作用并说明数据留存和未清理项，不删除共享资源。报告、已约定核验和必要清理完成后，只完成记录中匹配的本实验 Goal；负面或证据不足可以完成，但未知运行状态或未完成清理必须如实留在报告中，不能结束其他 Goal。

需要人类时使用可读说明：当前步骤、已完成内容、真正缺什么、推荐动作与候选、收到后从哪继续。工具/格式问题先由 Agent 核对修复，不把所有未知项转化为人工解锁门。
